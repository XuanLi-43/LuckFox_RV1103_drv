# Luckfox Pico Plus 设备树编译与烧录指南

> 目的：修改设备树（dts）只编译设备树 ，重新打包 boot.img ，更新到板子 ，板上验证
>
> **路径说明**：本文所有 `<SDK根目录>` 请替换为你本机 SDK 的实际路径（Docker 容器内对应 `/home`，见 §1）。
> 示例以 MD0240 LCD 模块（`MD0240_LCD`）为例，其他模块把目录名与节点名换成你自己的即可。

## 1. 环境说明

| 项目 | 值 |
|---|---|
| SDK 宿主路径 | `<SDK根目录>` |
| Docker 容器路径 | `/home`（与宿主是同一份文件，bind mount） |
| 编译环境 | Docker 容器（root 用户，无需 sudo） |
| 板子 | Luckfox Pico Plus（板载 Flash 启动，USB 烧录） |
| 内核设备树 | `rv1103g-luckfox-pico-plus.dts` |
| 内核配置 | `luckfox_rv1106_linux_defconfig` |
| 交叉编译器 | `arm-rockchip830-linux-uclibcgnueabihf-` |
| 编译输出目录 | `sysdrv/source/objs_kernel`（外部构建 `O=`） |
| 模块目录（你的驱动） | `sysdrv/drv_ko/my_drv/MD0240_LCD/`（全新 SDK 没有 `my_drv/`，需自建，见 README 第一节） |

**路径对应**（容器 = 宿主，同一份文件）：

```text
容器 /home/sysdrv/source/kernel                    = 宿主 <SDK根目录>/sysdrv/source/kernel
容器 /home/sysdrv/drv_ko/my_drv/MD0240_LCD          = 宿主 <SDK根目录>/sysdrv/drv_ko/my_drv/MD0240_LCD
```

## 2. 日常编译流程（改完 dts 后执行）

### 2.1 进入容器并设置 PATH（每次进容器都要）

```bash
sudo docker start -ai luckfox
```

容器内执行（**推荐写进 `~/.bashrc`，免去每次手动 export**）：

```bash
echo 'export PATH=$PATH:/home/tools/linux/toolchain/arm-rockchip830-linux-uclibcgnueabihf/bin:/home/sysdrv/out/bin/pc' >> ~/.bashrc
source ~/.bashrc
```

> 两个 PATH 缺一不可：`bin` 是交叉编译器；`out/bin/pc` 是 mkimage 等打包工具。

### 2.2 把你改好的 dts 覆盖到内核树（改完 dts 都要做）

```bash
# ① 备份原版（必须在覆盖之前做！.orig 是还原用的原版备份，见第 6 章）
cp /home/sysdrv/source/kernel/arch/arm/boot/dts/rv1103g-luckfox-pico-plus.dts \
   /home/sysdrv/drv_ko/my_drv/MD0240_LCD/rv1103g-luckfox-pico-plus.dts.orig

# ② 覆盖（仓库/模块目录里的版本覆盖内核原版）
cp /home/sysdrv/drv_ko/my_drv/MD0240_LCD/rv1103g-luckfox-pico-plus.dts \
   /home/sysdrv/source/kernel/arch/arm/boot/dts/
```

> 这步不能省：`make` 只编译内核树里的 dts，不编译你模块文件夹里的。不覆盖的话，编出来的是没改过的原版。

### 2.3 一条命令完成：编译 dtb + 重打包 boot.img

```bash
cd /home/sysdrv/source/kernel
make ARCH=arm CROSS_COMPILE=arm-rockchip830-linux-uclibcgnueabihf- \
  O=/home/sysdrv/source/objs_kernel \
  rv1103g-luckfox-pico-plus.img \
  BOOT_ITS=/home/sysdrv/source/kernel/boot.its -j4
```

成功标志：

```text
Image:  resource.img (with rv1103g-luckfox-pico-plus.dtb logo.bmp logo_kernel.bmp) is ready
Image:  boot.img (FIT image with Linux kernel, FDT blob and resource) is ready
```

### 2.4 验证并拷贝产物

```bash
# ① 验证 fdt 大小变了（加了节点会比原版大）
/home/sysdrv/out/bin/pc/mkimage -l /home/sysdrv/source/objs_kernel/boot.img | head -12
#    看 Image 0 (fdt) 的 Data Size

# ② 新 dtb 拷回你的模块目录
rm -f /home/sysdrv/drv_ko/my_drv/MD0240_LCD/rv1103g-luckfox-pico-plus.dtb
cp /home/sysdrv/source/objs_kernel/arch/arm/boot/dts/rv1103g-luckfox-pico-plus.dtb \
   /home/sysdrv/drv_ko/my_drv/MD0240_LCD/

# ③ 新 boot.img 覆盖镜像目录（后续烧录用）
cp /home/sysdrv/source/objs_kernel/boot.img /home/sysdrv/out/image_uclibc_rv1106/boot.img
```

## 3. 烧录（USB 方式，Windows 上用 SocToolKit）

> 我的板子是**板载 Flash 启动**（不插 SD 卡），用 USB 烧录更新 boot 分区。
> **SocToolKit 是 Windows 软件**。流程：Linux 上编译好镜像 → 拷贝到 Windows 机器 → 用 SocToolKit 烧录。
> 官方烧录教程：[镜像烧录 | LUCKFOX WIKI](https://wiki.luckfox.com/zh/Luckfox-Pico-Plus-Mini/Flash-image/)
> Windows 版 SocToolKit 在 SDK 的 `tools/windows/SocToolKit/` 里，直接拷走即可。

### 3.0 把镜像拷到 Windows（编译完成后）

```bash
# 需要拷的文件：SDK 输出目录 sysdrv/out/image_uclibc_rv1106/ 下的 boot.img（这次重新打包的新版）
# 用 U 盘/网盘/局域网拷贝到 Windows 机器

# 拷贝前必须先验证内容是新版（防止拷到旧文件白烧一次）：
strings /home/sysdrv/out/image_uclibc_rv1106/boot.img | grep md0240_lcd
#   → 必须输出 md0240_lcd（你的节点名）。搜不到 = 旧文件，别烧！
# 另外确保这个 boot.img 是从 objs_kernel 拷贝来的（2.4 ③ 步），时间戳应是今天
```

> 如果 `out/image_uclibc_rv1106/` 目录里缺 rootfs.img 等文件，说明之前的构建不完整，需要在容器里先 `./build.sh` 全量构建一次，生成完整分区镜像。

### 3.1 只更新 boot 分区（推荐——只改了设备树/内核时用）

1. Windows 上安装 USB 驱动 **DriverAssistant**（装完重启电脑）
2. 把新 boot.img 拷到 Windows（见 3.0），再验证一下是新的：`mkimage -l boot.img` → Created 应为当天、fdt Data Size 大于原版
3. 板子进入烧录模式：**按住 BOOT 键，用 USB 线连接电脑**（系统能登录时也可在板子上执行 `reboot loader`）
4. 打开 SocToolKit（**右键以管理员身份运行**），eMMC/Flash 模式下应识别到 loader 设备（设备显示 MaskRom/Loader）
5. 加载固件 → **只勾选 boot 分区和download**，选择新 boot.img → 点击 **"下载"**
6. 下载完成提示成功后，板子重新上电启动

> 只烧 boot 分区**不会动** Flash 里的 uboot、rootfs 等——板子其他部分保持原样，重启后设备树就是新的。

### 3.2 全量烧录 Flash（重装整个系统时用）

- 需要整套 **Flash 版镜像**：用 `BoardConfig-SPI_NAND-Buildroot-RV1103_Luckfox_Pico_Plus-IPC.mk` 配置在容器里 `./build.sh` 全量构建
- SocToolKit 分区模式勾选**全部分区**（env、idblock、uboot、boot、rootfs、oem 等）一起下载

## 4. 开发板验证

> 本模块的自定义节点为 `md0240_lcd@0`（`compatible = "atk_md0240,md0240_lcd"`），挂在 `&spi0` 下。
> 它在 `/proc/device-tree` 里以 `spi0/md0240_lcd@0` 呈现。

```bash
# ① 设备树节点在不在（节点名换成你自己的）
cat /proc/device-tree/spi0/md0240_lcd@0/compatible     # 应输出 atk_md0240,md0240_lcd
ls /proc/device-tree/spi0/md0240_lcd@0/                # 应有 dc-gpios、rst-gpios、pwr-gpios、status

# ② 板上回读 Flash 确认烧的就是新设备树（mtd3 是 boot 分区）
dd if=/dev/mtd3 of=/tmp/boot.img bs=1K 2>/dev/null
strings /tmp/boot.img | grep md0240_lcd                 # 搜到 = 烧录成功

# ③ 加载驱动验证
insmod /root/md0240_lcd.ko
dmesg | grep md0240                                    # probe 日志，无报错、出现 /dev/fb0
ls /dev/fb*
```
## 5. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `make: No rule to make target 'arch/arm/boot/dts/arch/arm/boot/dts/...dtb'`（路径重复两次） | 这个内核的顶层规则会自动加 `arch/arm/boot/dts/` 前缀，目标只能写**裸文件名** | 写 `make ... rv1103g-luckfox-pico-plus.dtb`，不要带路径 |
| `mkimage: command not found` / 打包那步静默失败（boot.img 还是旧的） | 容器 PATH 里没有 `sysdrv/out/bin/pc`（SDK 的 build.sh 会加，手动 make 不会） | `export PATH=$PATH:/home/sysdrv/out/bin/pc` |
| `arm-rockchip830-linux-uclibcgnueabihf-gcc: not found` | 工具链不在容器 PATH | `export PATH=$PATH:/home/tools/linux/toolchain/arm-rockchip830-linux-uclibcgnueabihf/bin` |
| `mkdir: Permission denied`（在宿主上编译时） | `objs_kernel` 是容器构建时留下的 root 属主目录 | 方案一：到容器里编译（root，无权限问题）；方案二：宿主上 `sudo chown -R $(id -un):$(id -gn) sysdrv/source/objs_kernel`（之后不要用 sudo 编译） |
| `*** The source tree is not clean, please run 'make mrproper'` | 源码树里有 `.config` / `include/config` 等残留（在内核目录跑过 defconfig 或普通编译造成） | `cd sysdrv/source/kernel && make ARCH=arm CROSS_COMPILE=arm-rockchip830-linux-uclibcgnueabihf- mrproper`，然后再执行 2.3 |
| `sudo: 'cd': command not found` | 把 `sudo` 加在了 `cd` 前面 | 不要给 make/cd 加 sudo（容器里本来就是 root；宿主上编译也不要 sudo，会留下 root 文件） |
| `objs_kernel/Makefile: /home/sysdrv/source/kernel/Makefile: No such file` | 在 objs_kernel 目录里直接执行了 make（那是 kbuild 生成的 stub，路径是容器旧环境写死的） | 不要在 objs_kernel 里执行 make；在源码目录执行并带 `O=`（见 2.3） |
| `git: detected dubious ownership in repository at '/home'` | 容器内 root 访问 /home 的常规提示 | 忽略，不影响编译 |
| 编译出的 dtb 是旧的（时间戳不对） | 拷贝步骤在编译之前执行了，拷到的是旧文件 | 按 2.4 顺序：先编译 → 验证 → 再拷 |

## 6. 还原到原始设备树
> 备份约定（第 2.2 步）：**改动前**先把内核树原版备份成 `MD0240_LCD/rv1103g-luckfox-pico-plus.dts.orig`，之后还原就是"把 .orig 拷回内核树"。

涉及**两个文件夹**（容器和宿主是同一份文件，任选一边操作即可）：

| 文件夹 | 容器路径 | 宿主路径 |
|---|---|---|
| A. 内核树（编译用的） | `/home/sysdrv/source/kernel/arch/arm/boot/dts/` | `<SDK根目录>/sysdrv/source/kernel/arch/arm/boot/dts/` |
| B. 模块目录（MD0240_LCD） | `/home/sysdrv/drv_ko/my_drv/MD0240_LCD/` | `<SDK根目录>/sysdrv/drv_ko/my_drv/MD0240_LCD/` |

### 6.1 恢复原版 dts

**前提**：B 文件夹里的 `.orig` 是原版备份（按第 2.2 步在改动前备份的）。

**用 `.orig` 还原**（拷贝方向：B → A）：

```bash
# 从 B 文件夹的 .orig 拷出 → 覆盖 A 内核树的 dts
cp /home/sysdrv/drv_ko/my_drv/MD0240_LCD/rv1103g-luckfox-pico-plus.dts.orig \
   /home/sysdrv/source/kernel/arch/arm/boot/dts/rv1103g-luckfox-pico-plus.dts
```

验证还原干净（应无输出）：

```bash
grep -n "md0240_lcd" /home/sysdrv/source/kernel/arch/arm/boot/dts/rv1103g-luckfox-pico-plus.dts
```

还原完成后三个文件的位置和内容：

| 文件 | 在哪个文件夹 | 内容 |
|---|---|---|
| `rv1103g-luckfox-pico-plus.dts` | A（内核树） | 原版（还原后） |
| `rv1103g-luckfox-pico-plus.dts` | B（MD0240_LCD） | 你改过的版本（保留，随时可恢复） |
| `rv1103g-luckfox-pico-plus.dts.orig` | B（MD0240_LCD） | 原版备份（还原的来源） |

（如需恢复你改过的版本，把 B 文件夹里的 dts 拷回 A 覆盖即可，就是第 2.2 步的覆盖操作。）

### 6.2 重新打包 boot.img

**docker环境下**
```bash
cd /home/sysdrv/source/kernel
make ARCH=arm CROSS_COMPILE=arm-rockchip830-linux-uclibcgnueabihf- \
  O=/home/sysdrv/source/objs_kernel \
  rv1103g-luckfox-pico-plus.img \
  BOOT_ITS=/home/sysdrv/source/kernel/boot.its -j4
```
### 6.3 验证是原版内容

```bash
# 必须搜不到 md0240_lcd（搜到 work 是正常的，原厂节点）
strings /home/sysdrv/source/objs_kernel/boot.img | grep md0240_lcd   # 无输出 = 对
strings /home/sysdrv/source/objs_kernel/boot.img | grep work         # 有输出 = 对
```

### 6.4 拷贝 + 烧录 + 验证

```bash
cp /home/sysdrv/source/objs_kernel/boot.img /home/sysdrv/out/image_uclibc_rv1106/boot.img
```

拷到 Windows → SocToolKit 只勾 boot 分区重烧 → 板子断电重启 → 板上验证：

```bash
ls /proc/device-tree/spi0/ | grep md0240_lcd   # 应没有输出（原版 dts 无该节点）
```

以后想恢复你改的版本，把 6.1 改成反向拷贝即可（MD0240_LCD 文件夹里的 dts 拷回内核树），再走 6.2~6.4。
